# 系统切换应用

[English](switch-app.md)

两侧使用同一份逻辑和独立 APK：`stock` 保留澎湃OS 启动器图标，
`google` 使用圆形兼容图标与自适应图标。界面跟随系统语言，默认英文，
`zh` 使用中文。安装 APK 不会安装 Google 系统或建立恢复通道。

## 构建与安装

按[英文构建命令](switch-app.md#build)分别生成两种 APK，使用自己的签名密钥，
后续更新保留同一密钥。配置中的镜像哈希、串口撤销和运行验证必须来自本机；
不能使用测试文件里的占位值。

在澎湃OS 中安装 `stock` 版本：

```sh
adb -s TV_STOCK_ADB_SERIAL install /private/new-stock-app-build/switch.apk
```

进入临时 Google 后，用对应 ADB 目标和 `google` APK 路径安装另一侧。
两侧应用数据独立。命令不允许覆盖或降级；发现已有应用时，先核对签名、
版本和安装状态，不要用卸载或清数据来绕过安装失败。

## 首次配置开机服务

仍在澎湃OS、尚未创建共享默认目录时，运行
[`provision-switch-startup.py inspect`](switch-app.md#first-install-startup-binding)，
传入已审核 APK、构建结果、两份 SHA-256 和独立记录的设备绑定。
检查后用新日志目录执行 `enable`。

工具核对原厂 B、普通 ADB、已安装 APK 和共享目录尚不存在，然后打开应用、
允许后台运行，并将开机服务加入无障碍服务列表。其他服务和 ADB 辅助程序均保留。
这个服务不接收界面事件，不读取窗口内容，也不执行手势。

此时安装未完成，应用显示暂不可用是预期行为。工具不会创建默认目录、选择
Google、写启动参数或重启。共享状态只在后续[提交日常文件](first-install.zh-CN.md#提交日常文件)
时建立，避免临时安装环境下次启动被自身的保护条件拒绝。

每次设置修改均记录并回读。中断或其他程序改动设置时停止，不自动重试或覆盖。
完成仅表示配置已写入，不代表系统已经绑定服务，也不代表开机切换通过。
此首次配置工具已通过离线测试，尚未用于全新电视。

## 启动检查与错误提示

支持原厂的 `cold`、`reboot` 和 `warm` 三种启动原因。固定哈希只忽略启动原因
和有效的背光数值，其余启动参数必须保持匹配。第 5 版误拒绝 `warm`，
导致用户重启后自动进入和手动切换都失败。第 6 版接受此值，
不改写保存的启动原因，也不改变启动转换流程。

应用会用中英文区分启动配置不匹配、文件缺失、系统服务不可用等原因。
原始异常保留在 `CodexSystemSwitch` 日志中。

## 名称与兼容

原厂系统名为 **小米澎湃OS / Xiaomi HyperOS**。参考版本
`OS2.0.5.0.RFTMATV` 基于 Android 11。

状态文件中的 `XIAOMI`、构建参数 `stock` 及已有动作和文件名是兼容标识，
不随显示名称修改。改界面名称不会迁移或清除任一系统的数据。
